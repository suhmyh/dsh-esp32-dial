# DSH × ESP32-S3 集成方案

**硬件**：Waveshare ESP32-S3-Touch-LCD-1.85B（1.85" 圆屏，360×360，触摸，麦克风，喇叭，IMU，WiFi，锂电）  
**目标**：让 DeepSeek Harness 智能体与这个桌面硬件双向通信——DSH 在它上面实时显示状态、接收触控指令、通过麦克风语音输入、通过喇叭语音输出。

---

## 一、硬件能力总览

| 外设 | 型号 / 协议 | 可用于 |
|------|-------------|--------|
| **屏幕** | ST77916, QSPI, 360×360, 262K 色 | 显示 DSH 状态、任务列表、日志 |
| **触摸** | CST816, I2C | 点击按钮切换页面、确认/取消操作 |
| **麦克风** | I2S 数字麦克风 | 语音输入 → 转文字提交给 DSH |
| **喇叭** | 8Ω 2W + PCM5101 DAC | DSH 语音回复、通知提醒音 |
| **IMU** | QMI8658, 六轴陀螺仪+加速度计 | 手势控制（摇一摇取消、倾斜滚动） |
| **RTC** | PCF85063 | 离线计时、定时唤醒 |
| **TF 卡** | SPI | 存储日志、录音文件、离线缓存 |
| **电池** | 3.7V 锂电 + 充电管理 | 无绳运行，桌面随处放 |
| **WiFi** | 2.4GHz 802.11 b/g/n | 与 DSH 机器同局域网通信 |
| **USB** | Type-C | 固件烧录 + 串口调试 |
| **空闲 GPIO** | 1, 3, 4, 5, 14, 16, 17, 18, 21, 40, 41, 42, 45, 46 | 外接传感器（温湿度、红外、继电器） |

## 二、三条路线（按可行性排）

### 路线 A ⭐ **DSH ↔ ESP32 双向桌面伴侣**（推荐起点）

DSH 和 ESP32 通过 WiFi 局域网双向通信，各管各的：

```
┌─────────────────────┐      WiFi LAN       ┌──────────────────────┐
│  DSH  (Windows)      │                     │  ESP32-S3-Touch-LCD  │
│                      │  WebSocket / HTTP   │                      │
│  ┌───────────────┐   │ ◄──────────────────► │  ┌────────────────┐ │
│  │ MCP 桥接进程    │   │                     │  │ LVGL 触摸 UI    │ │
│  │ (Node.js)      │   │                     │  │ ┌状态/任务/日志┐│ │
│  │                │   │                     │  │ │按钮/语音/手势││ │
│  │ 工具:          │   │                     │  │ └──────────────┘│ │
│  │  .show_status  │   │                     │  └────────────────┘ │
│  │  .speak        │   │                     │  ┌────────────────┐ │
│  │  .voice_input  │   │                     │  │ 传感器/执行器   │ │
│  │  .sensor_data  │   │                     │  │ (IMU/麦克风/屏) │ │
│  │  .set_led      │   │                     │  └────────────────┘ │
│  └───────────────┘   │                     └──────────────────────┘
│                      │
│  ┌───────────────┐   │
│  │ DSH 智能体     │   │
│  │ (调用 MCP 工具) │   │
│  └───────────────┘   │
└─────────────────────┘
```

**ESP32 角色**：独立的带屏遥控器/状态面板，同时暴露传感器（麦克风/IMU/电池）给 DSH  
**DSH 角色**：通过 MCP 桥调用 ESP32 的功能，同时接收 ESP32 发来的状态推送

**典型案例**：
- "帮我查一下任务进度" → 桥接进程 → ESP32 屏幕显示当前任务列表
- "帮我把屏幕亮度调到 50%" → 桥接进程 → ESP32 调背光
- "摇一摇取消当前提问" → ESP32 检测到摇晃 → 通知 DSH 取消

**为什么推荐这条**：只用一条路线就把屏幕、触摸、麦克风、喇叭、IMU 全用上了，实现完立刻能演示"语音问 DSH + 屏幕显示状态"。

---

### 路线 B **ESP32 当纯遥控器/状态屏**

路线 A 的子集，砍掉 DSH 主动控制 ESP32 的部分，只做：
- ESP32 定时轮询 DSH 的 `/api/session.list` 或 `/api/jobs.list` → 显示状态
- 触摸按钮 → 触发 DSH 的 `/api/rpc` 调用（如 `session.cancel`）

**优点**：不需要 MCP 桥，ESP32 用 HTTP 直接与 DSH 通信  
**缺点**：单向轮询，交互延迟高，没有语音/喇叭利用

不推荐作为独立路线，但其方案可以**合并到路线 A 的 v1 里程碑**里。

---

### 路线 C **语音/视觉入口**

ESP32-S3-Touch-LCD-1.85B 有麦克风 + 喇叭，但没有摄像头。所以"视觉入口"不适用。语音可以做：

- **ESP32 侧**：按下触摸按钮开始录音 → 保存到 TF 卡 → 通过 WebSocket 发送音频文件到桥接进程
- **桥接进程侧**：接收音频 → 调用 DSH 的 `attachment` API 上传 → 智能体分析音频内容
- **DSH 侧**：智能体看到音频附件，描述听到了什么

**局限**：ESP32-S3 的麦克风是单声道，质量一般，不适合复杂的语音识别场景。如果要做 ASR，建议用 DSH 所在机器的语音识别（Windows 语音 API 或云端 ASR），ESP32 只负责采集音频流。

**评估**：功能可以做，但受限于板载麦克风质量，体验可能不如直接对着电脑说。建议作为**路线 A 的 v2 追加功能**，不单独起步。

## 三、通信协议选型

| 协议 | 方向 | 用途 | 延迟 | 推荐 |
|------|------|------|------|------|
| **WebSocket** | 双向 | 实时状态推送（ESP32 订阅 DSH 状态变化）、音频流 | 实时 | ⭐ 主通道 |
| **HTTP REST** | 单向 | 触控按钮触发 DSH 操作、ESP32 查询状态 | 秒级 | 辅助通道 |
| **MQTT** | 双向 | 多设备/远程场景——VPS 上跑 broker，ESP32 和 DSH 都连它 | 实时 | 路线 A v2 |
| **USB 串口** | 双向 | 调试、烧录、有线通信 | 实时 | 调试用 |

**v1 推荐**：WebSocket + HTTP。WebSocket 用于 ESP32 到 DSH 的实时状态订阅和音频流，HTTP 用于触控操作和查询。

**v2 推荐**：加入 MQTT，通过你在 VPS 上已有的 frps 同机跑一个 mosquitto broker，这样 ESP32 通过公网 MQTT 也能从外网控制 DSH（ESP32 出站不受 NAT 限制）。

## 四、架构详述

### 4.1 ESP32 固件层

**框架**：Arduino + LVGL 9  
**原因**：Waveshare 官方提供 Arduino 例程（含 LVGL 触摸 demo），PlatformIO 管理依赖，SquareLine Studio 可拖 UI 设计

**固件模块**：

```
┌─────────────────────────────────────────────────┐
│  ESP32 固件                                       │
│                                                   │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐ │
│  │ WiFi 管理  │  │ WebSocket │  │ HTTP 服务器      │ │
│  │ (自动重连) │  │ 客户端     │  │ (REST API)      │ │
│  └──────────┘  └──────────┘  └────────────────┘ │
│  ┌──────────────────────────────────────────────┐│
│  │ LVGL 触摸 UI                                  ││
│  │  ┌─────────────────────────────────────────┐ ││
│  │  │ 页面: 主页 / 状态 / 任务 / 日志 / 设置    │ ││
│  │  │ 组件: 按钮、滑块、列表、进度条、波浪动画  │ ││
│  │  └─────────────────────────────────────────┘ ││
│  └──────────────────────────────────────────────┘│
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐ │
│  │ I2S 音频  │  │ IMU 手势  │  │ 电池/电源管理   │ │
│  │ (录音/放音)│  │ (QMI8658)│  │ (充电/电量)     │ │
│  └──────────┘  └──────────┘  └────────────────┘ │
└─────────────────────────────────────────────────┘
```

**UI 页面规划**：

| 页面 | 内容 | 交互 |
|------|------|------|
| **主页** | 当前会话状态、智能体头像、一句话摘要 | 点击进入详细状态页 |
| **状态** | 当前任务进度条、等待队列数、会话时间 | 滑动滚动 |
| **任务** | 当前任务列表（名称、进度、耗时） | 点击任务查看详情 |
| **日志** | 最近 20 条日志流（实时滚动） | 自动滚动，可暂停 |
| **设置** | WiFi 配置、DSH 地址、亮度、音量 | 滑块/按钮 |

**通信协议（ESP32 侧）**：

```
WebSocket 端点: ws://<dsh-host>:<bridge-port>/ws
  ESP32 → DSH:   { type: "command", action: "cancel" | "pause" | "approve" }
                  { type: "audio", data: "<base64>" }
                  { type: "sensor", imu: {...}, battery: 85 }
  DSH → ESP32:   { type: "status", session: "running", task: "..." }
                  { type: "display", page: "status", payload: {...} }
                  { type: "speak", text: "任务已完成" }
                  { type: "notification", level: "info", message: "..." }

HTTP 端点: http://<dsh-host>:<bridge-port>/api/
  ESP32 GET /api/v1/status      → 查询 DSH 状态
  ESP32 POST /api/v1/command    → 发送命令
  POST /api/v1/audio/upload     → 上传音频文件
```

### 4.2 DSH 侧：MCP 桥接进程

**语言**：Node.js（本机已有 Node 24）  
**依赖**：`ws`（WebSocket 服务器）、`mqtt`（v2 用）、`node-fetch`（或内建 `fetch`）

**MCP 工具暴露给 DSH 智能体**：

| 工具名 | 参数 | 说明 |
|--------|------|------|
| `esp32.speak` | `text: string` | 让 ESP32 通过喇叭朗读文本 |
| `esp32.show_status` | `page: string, payload?: object` | 切换 ESP32 屏幕显示页面 |
| `esp32.show_notification` | `message: string, level?: "info"\|"warn"\|"error"` | 在 ESP32 上显示通知 |
| `esp32.voice_input` | `duration?: number` | 启动 ESP32 录音，返回音频 |
| `esp32.sensor_data` | — | 读取当前 IMU 数据和电池电量 |
| `esp32.set_brightness` | `level: number (0-100)` | 调节屏幕亮度 |
| `esp32.set_volume` | `level: number (0-100)` | 调节喇叭音量 |
| `esp32.ping` | — | 检查 ESP32 连接状态 |

**MCP 注册方式**：DSH 已有 `dsh-mcp-client` 插件，支持在 settings 中注册外部 MCP 服务器。桥接进程作为独立 Node 进程启动，MCP 协议通过 stdio 或 TCP 与 DSH 通信。

### 4.3 安全考虑

| 风险 | 方案 |
|------|------|
| **ESP32 指令被局域网内他人伪造** | ESP32 与桥接进程之间使用预共享 Token（HMAC），每次请求携带 |
| **DSH 被 ESP32 过度调用** | 桥接进程限速（复用 `createLimiter` 模式） |
| **公网暴露** | 默认只在 LAN 通信；远程场景走 MQTT（broker 需要认证），或通过已有网关反向代理 |
| **音频隐私** | 录音只在用户主动触发时开始，不持续监听 |

## 六、你需要准备什么

| 事项 | 说明 |
|------|------|
| **Type-C 数据线** | 烧录固件 + 调试串口，最好两根（一根烧录一根供电） |
| **Arduino IDE** | 或 PlatformIO（VS Code 插件），用来写/编译/烧录 |
| **ESP32 板级支持** | Arduino 里装 `esp32` 包（板管理器搜 ESP32-S3），Waveshare 官方提供 |
| **LVGL 库** | Arduino 库管理器搜 `lvgl` 9.x |
| **WiFi 环境** | 板子和 DSH 机器在同一个局域网 |
| **3.7V 锂电池**（可选） | MX1.25 接口，任何航模电池/18650 都行，无绳桌面体验 |

**我不需要的东西**：额外的硬件、VPS 改动、FRP 配置、DSH 重启——这些我都已经可以在 Windows 侧和代码侧完成。
